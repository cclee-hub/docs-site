证书到期监控每天报同一个服务证书「剩 20 天」，可端口在线实测显示现役证书要到 2027-02-08 才到期——告警与现实差了两年多。

在为客户提供 [行业龙头制造企业中国全托管](/cases/waterpark-china-hosting-migration) 时定位到这个告警误报——证书到期监控是那台 cPanel 服务器的常设巡检项。

## TL;DR

误报的根源是「最短天数 ≠ 现役证书」：cPanel 服务证书目录（`/var/cpanel/ssl/system/certs/`）会累积历史代次文件，多代共存、互不删除；按 PEM 文件逐个扫描的监控把已过期但无引用的旧代次也算进来，其负天数永远小于 21 天阈值，告警于是每天重复。处置路径：核目录内 `*-NOT_AFTER` 标记 + `s_client` 在线实测确认现役 → 删除无引用的陈旧代次（crt 及 .cache）→ 告警下轮扫描自愈，在线服务无损。

## 问题现象：证书告警天天报，现役证书却还剩两年多

告警内容是证书剩余天数的最小值：某服务证书 20 天后到期，且每天都在重复——过一次阈值就报一次，看上去像一张「永不过期也永远临期」的证书。

按告警去核现实，对不上号。四类服务端口的在线实测（`s_client` 直连看证书）全部指向同一张新一代证书：NOT_AFTER 标记 1802123049，换算即 2027-02-08。目录里那张「剩 20 天」的证书——Let's Encrypt 历史代次，9 月 11 日签发、12 月 10 日到期——没有任何服务引用它。它早已过期，却没有惊动任何在线服务，只惊动了监控。

## 根因：证书目录多代共存，文件扫描不看引用

cPanel 安装服务证书的方式是向 `system/certs/` 目录累积写入：每次续期/换发新增一代文件，旧代次留在原地，不做清理。目录里因此长期共存多代证书文件。

监控侧的扫描按 PEM 文件嗅探：逐文件读证书、逐文件算剩余天数，不查「哪个服务正在引用哪张」。主机名过滤又是子串包含式——同一域名的多代证书 CN 相同，过滤条件区分不出谁现役谁过期。于是最旧那张过期代次的剩余天数恒为负、恒小于 21 天的告警阈值，扫描一轮报一轮。告警没有说谎——它忠实地报告了目录里最旧的文件；说谎的是「目录里天数最短的文件 = 现役证书」这个默认假设。

## 解决方案：NOT_AFTER + 在线实测定现役，删无引用代次

处置分四步，判据先行：

```bash
# 1. 目录内每张证书旁有 NOT_AFTER 标记文件（epoch 时间戳），先核标记
ls /var/cpanel/ssl/system/certs/
cat /var/cpanel/ssl/system/certs/*-NOT_AFTER
# 现役代次标记 1802123049 → date -r 1802123049 → 2027-02-08

# 2. 端口在线实测，确认服务实际出示的证书
openssl s_client -connect <主机名>:2083 </dev/null 2>/dev/null \
  | openssl x509 -noout -enddate
# 输出应与现役 NOT_AFTER 一致
```

```bash
# 3. 标记与实测都指向「非现役」且无引用后，删除陈旧代次（crt + .cache）
rm /var/cpanel/ssl/system/certs/<陈旧代次>.crt
rm /var/cpanel/ssl/system/certs/<陈旧代次>.cache

# 4. 复核：服务无损 + 告警自愈
openssl s_client -connect <主机名>:2083 </dev/null 2>/dev/null | head -1
openssl s_client -connect <主机名>:993  </dev/null 2>/dev/null | head -1
```

实操结果（2026-11-22）：删除后 2083 与 993 端口服务无损，告警下一轮扫描起不再重复——目录里最短的剩余天数变成了现役证书的真实天数，监控口径与线上现实重新对齐。这套「按文件扫描 + 结论式告警」的巡检属于 [CCLee 服务器哨兵](/docs/server-sentinel) 的证书监控——告警归并成结论并附处置指引；类似的证书签发侧问题（AutoSSL 不签发）另见 [cPanel AutoSSL 不签发证书？排除列表与 vhost 证书路径](/blog/cpanel-autossl-not-issuing)。

<InfoBox variant="warning" title="注意事项">

- 判读证书告警的顺序：先核 NOT_AFTER 标记与端口在线实测，再决定动作——剩余天数最短者未必现役。
- 只删确认无引用的文件；现役证书与其 .cache 不动。
- 删除后复核两个动作：服务端口实测无损、告警下一轮消失，缺一不可。
- 同域主机名的多代证书 CN 相同，子串式过滤区分不了代次——别指望过滤条件，直接核标记。

</InfoBox>

## 常见问题

### 证书到期告警一直在报，该怎么办？

先判现役再动手：核 /var/cpanel/ssl/ 下的 *-NOT_AFTER 标记文件，并用 s_client 在线实测端口证书的实际到期日。案例里告警的「剩 20 天」来自历史代次文件，现役证书实测 2027-02-08 才到期。确认告警对象是无引用陈旧文件后删除（crt 及 .cache），告警下轮扫描自愈，不需要换证书。

### 怎么确认哪张证书是现役的？

两个判据交叉：目录内证书旁的 *-NOT_AFTER 标记文件（epoch 时间戳），与端口在线实测（s_client 看证书实际到期日）对照；现役证书两个值应一致。仅凭文件名、签发时间或监控面板的最短剩余天数都不可靠——实测案例里最短的 20 天恰恰来自无引用的历史代次。

### 删除历史代次证书文件会影响在线服务吗？

只删确认无引用的文件（crt 及其 .cache），现役证书不动。实操删除后 2083 与 993 端口服务无损，告警下一轮扫描即自愈。动手前提是判据先行：NOT_AFTER 标记与在线实测都指向「非现役」才删除。
