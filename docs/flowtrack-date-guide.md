# 交期与日期怎么算

## 先记住三件事

1. 所有日期都按**日历天**算（自然日），周六周日、节假日照算工期，没有「工作日扣减」。
2. 「今天」按北京时间算。
3. 系统不是排一次就死板执行——每报一次完工、每过一天，后面的日期都会跟着重估。你看到的数字永远是「按现在的进度推下去」的结果。

## 新工单的交期：启动日 + 路线总工期

新建工单选好工艺路线后，交期自动算好：**启动日 + 路线总工期 = 默认交期**。比如路线一共 7 天，今天（11/26）立项，交期就是 12/03。觉得不合适可以直接改交期（加急单把交期改近，系统后面会提前提醒）。

<img src="/images/docs/flowtrack/20-01-new-order-due.webp" width="640" loading="lazy" />

交期在确认立项后就定下来了。后面要做的是盯着「预计完工」和交期比，发现要晚就在决策页处理（见下文）。

## 每道工序哪天干：顺着路线排

工序列表里每道工序的日期是系统按路线前后关系排出来的：

- **前道完了我才开始**：这道的开工日 = 前道的完工日，开工日 + 这道的天数 = 这道的计划完工日。行上的「MM/DD 完」就是计划完工日。
- **几道并行**：同一前道带出来的几道工序**同一天开工**，各干各的，全部干完才进下一道。

下面这张单是纯串行：下料 11/27 完 → 机加 11/29 完 → 焊接 11/30 完 → 组装 12/02 完 → 检验 12/03 完，一天接一天，最后检验完工那天就是交期。

<img src="/images/docs/flowtrack/21-02-serial-detail.webp" width="640" loading="lazy" />

## 行上的灯和字怎么看

工序行左侧的圆点加状态字，就是这道活现在的样子：

- **黄点 ·「还有 N 天」**：快到应完日了（默认提前 3 天开始提醒），还没报完工。
- **红点 ·「未开始 · 逾期 N 天」**：这道按理早该干完，到现在还没报完工。这是在催这道活赶紧安排，**不等于整张工单要晚**（整单晚不晚看「预计完工」，见下文）。
- **绿点 ·「已完成」**：报过完工了。

「应完日」是系统给这道定的「最晚几号干完才不拖别人」：等前道全部实际干完后，应完日 = 前道实际完工日 + 这道的天数。前道还没全干完时，系统不给这道定应完日——日期没定，晚也没法怪这道。

下面这张并行路线的工单：开料、抛光已报完成（绿点）；机加的应完日是 11/24，今天 11/26 还没干完，所以红字「未开始 · 逾期 2 天」；总装排 11/25 完，前道（机加、抛光）还没全完，灰点正常等。画布里机加标红，表示它是当前最慢的一条线。

<img src="/images/docs/flowtrack/22-03-parallel-ontime-detail.webp" width="640" loading="lazy" />

注意一个细节：**已完成的行不再显示逾期红字**——哪怕这道实际完工日晚于应完日（报工时已经填过延期原因，账记在那次报工里，不再挂红字催你）。行上显示的日期是计划完工日，实际哪天干完的，点开这道工序能查到。

## 前道拖了，我这道跟着顺延

前道实际完工晚了，后面没开工的工序自动顺延，行上会写清楚：**「计划 MM/DD → 应完工 MM/DD（前道延误 N 天）」**。延的天数记在前道头上，不怪这道。

下图：总装原计划 11/25 完，因为机加实际 11/26 才完工（晚了 2 天），总装顺延为应完工 11/27，行上明确标「前道延误 2 天」。

<img src="/images/docs/flowtrack/24-05-parallel-late-detail.webp" width="640" loading="lazy" />

## 报完工为什么让选延期原因

点「完成」报完工时先选日期（今天 / 昨天 / 前天 / 选日期）。**如果选的完成日晚于这道应完日，必须选一个延期原因**——前道延误、设备占用、料未到、返工、供应商延误，或选「其他」并补一句说明。这是强制的一步，不选原因交不了。

<img src="/images/docs/flowtrack/27-08-report-reason.webp" width="640" loading="lazy" />

选原因不是为了追责，是为了月底统计晚单都晚在哪一环（统计页有汇总）。准点报完工什么都不用填，一下就过。

## 整单会不会晚：看「预计完工」

系统随时在估「照现在这个进度，整张单几号能全部做完」：

- 已完成的工序，按实际完工日算；
- 正在做的工序，至少算到今天（不可能比今天更早完）；
- 没开工的工序，按前后顺序往后推。

估出来的日子和交期一比，就是列表卡和表格右上那行字：**「准时」/「早 N 天」/「预计晚 N 天」**。

下面表格里三张并行路线的工单正好是三种状态：261126-03 机加 11/26 才完工（应完 11/24），把总装推后 2 天，整单「预计晚 2 天」；261126-02 和 261126-04 都有机加红字逾期，但整单仍然「准时」——逾期只是催那道活，不是判整单死刑。

<img src="/images/docs/flowtrack/26-07-table-parallel.webp" width="640" loading="lazy" />

## 预计晚 N 天：去决策页当场处理

点列表卡上的「去处理 ›」（或通知里的「交期预警」）进决策页。页面直接给结论、原因和三个动作：

<img src="/images/docs/flowtrack/25-06-decision-late.webp" width="640" loading="lazy" />

**晚的原因**：系统找出真正把整单拖晚的那几道工序，列出「谁、晚几天、派给谁」。上面例子里就是机加晚 2 天——抛光虽然也晚完了 2 天，但没有拖到整单，所以不列它（道理见下一节）。

三个动作：

1. **改天数**：给某道工序加减天数。下面的试算行实时告诉你改完的结果——「预计 11/27 · 仍预计晚 2 天」就是提醒你光改这道救不回来。确认后，这道工序后面的所有工序整体顺延，可以选择同时通知被改工序派给的人。
2. **改交期**：和客户重新商量过了，把交期改成新日子。改完「预计晚 N 天」自然消失。
3. **暂不处理**：先放着，列表里这张单继续挂「预计晚 N 天」。

页面底部的提醒是操作原则：**先看影响再确认，确认后回列表**。

## 一道工序晚了，整单为什么还能准时

并行路线常有富余：两道工序同时开工，下一道要等**最慢的那道**做完才开始。快的那道就算晚完几天，只要没超过慢那道的时间，整单一点不受影响。

下面这张单：机加要干 3 天，抛光只干 1 天，总装要等机加。抛光实际 11/24 才完工（比应完日 11/22 晚了 2 天，报工时也照实填了原因），但机加本来就要干到 11/24，总装 11/24 照常开工——整单预计 11/25 交，交期 11/25，**准时**。

点进决策页验证：只显示绿色的「准时」，交期和预计同一天，**没有任何原因区**——系统不冤枉做快的工序。

<img src="/images/docs/flowtrack/23-04-decision-ontime.webp" width="640" loading="lazy" />

反过来说：如果晚完的这道恰好是最慢的那道，整单就会被推晚，决策页会把它的名字列进「晚的原因」。

## 一页速查

| 你看到的 | 意思 |
| --- | --- |
| 启动日 + N 天（路线总工期）= 默认交期 | 新工单交期的来源，可手改 |
| MM/DD 完 | 这道工序的计划完工日 |
| 还有 N 天（黄） | 快到应完日，还没报完工（默认提前 3 天提醒） |
| 未开始 · 逾期 N 天（红） | 应完日过了还没报完工，催这道活；不代表整单晚 |
| 已完成（绿） | 已报完工，行上日期是计划完工日，实际完工点进去查 |
| 前道延误 N 天 | 被前道拖了 N 天，账在前道头上 |
| 准时 / 早 N 天 / 预计晚 N 天 | 整单预计完工和交期的差 |
| 晚的原因：某工序 晚 N 天 | 把整单拖晚的工序（决策页） |
